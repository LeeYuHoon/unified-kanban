# 운영 릴리스 장치 번호 재검증

이 명령은 설치·업데이트가 자동으로 실행하는 복구가 아닙니다. 유지관리자가 특정 운영 릴리스와 기존 완료 영수증을 직접 검토하고 승인한 경우에만 사용합니다.

재부팅이나 재마운트 이후 장치 번호가 달라질 수 있습니다. 그러나 기존 v2 영수증에는 안정적인 볼륨 식별자가 없어, 번호 차이만으로 같은 볼륨임을 증명할 수 없습니다. 파일 내용이 같아도 이전 디렉터리의 출처가 이어진다는 증거는 아닙니다. 이 한계를 받아들이는 명시적 승인이 먼저 필요합니다.

## 허용 범위

- 현재 선택된 릴리스 하나만 대상으로 합니다.
- 검토한 upstream·carried SHA와 기존 영수증의 SHA-256을 모두 지정합니다.
- 장치 번호 외에는 inode, Git 정보, 바이트코드, 전체 릴리스 파일 해시 등 모든 완료 필드가 같아야 합니다.
- 실행 파일, 대화 데이터, 릴리스 선택 파일은 수정하지 않습니다. 기존 영수증의 정확한 세대만 조건부 교체합니다.
- 파일·디렉터리 교체나 내용 변경이 감지되면 거부합니다. 실패 후 외부에서 교체된 파일은 덮어쓰지 않습니다.
- 적용 후 원래의 전체 릴리스 검사와 런타임 호환성 검사를 다시 실행합니다. 검사 자체를 완화하거나 생략하지 않습니다.

## 실행 방법

먼저 읽기 전용 검사로 결과를 확인합니다. 아래 값은 실제 검토한 값으로 각각 지정해야 합니다.

```sh
python3 scripts/hermes-release-manager.py reattest-device /절대/경로/hermes-agent \
  --reviewed-upstream 검토한_upstream_SHA \
  --reviewed-carried 검토한_carried_SHA \
  --expected-receipt-sha256 검토한_기존_영수증_SHA256
```

명시적 승인 후 같은 명령에 `--apply`를 추가합니다. 기본 실행은 기록을 쓰지 않습니다. 적용 결과가 `applied`인지 확인하고, 일반 setup 및 실제 카드 수집을 별도로 검증합니다. 기록 갱신 성공은 설치나 실사용 검증 완료가 아닙니다.

적용 후에는 영수증 해시가 바뀝니다. 예전 해시를 사용한 재시도는 거부되며, 자동으로 새 기록을 신뢰하지 않습니다. 새 영수증을 다시 검토한 경우에만 그 해시로 호출할 수 있고, 이미 현재 장치와 일치하면 `already-current`로 쓰기 없이 종료합니다.

교체 중 경쟁이나 복원 I/O 실패가 발생하면 `NamespaceAuthorityError`가 정식 이름의 관측된 권한(`producer`, `displaced`, `unknown`)과 보존 경로를 보고합니다. 복원은 비어 있는 정식 이름에만 배타적으로 수행하며, 새 외부 파일을 교환하거나 덮어쓰지 않습니다. 복원이 불가능하면 생성 파일과 밀려난 파일을 보존하고 실패합니다. 보존된 private 파일은 자동 재시도 권한이 아니므로 삭제하거나 정식 이름으로 직접 옮기지 말고 별도 검토하세요. 디렉터리 동기화 실패는 현재 파일이 보이더라도 충돌 후 영속성을 보장하지 않습니다.

권한·소유권·내용이 달라진 릴리스, 복사한 영수증, 다른 릴리스 선택을 이 명령으로 복구하려 하지 마세요. 실패하면 보고된 원인을 조사하고 원래 파일을 보존합니다. 영수증 삭제나 직접 편집으로 설치 검사를 우회하지 않습니다.
